# SDK review007 — runtime evidence before live access

Independent compile found3test HeadersInit typing errors (Codex repaired with new Headers). The synthetic UUID fixtures were invalid; Codex fixed them to valid version4/variant8or9 UUIDs. The existing48SDKtests now pass. That does NOT establish the missing guarantees below. No live calls or credentials were used.

## Proven defects

1. A disposable real Node probe submitted two ReservationLedger.reserve calls with Promise.allSettled against one ledger: BOTH fulfilled (expected1). _activeKey is set only after await append. Separate ledger instances also cache stale history. Disk append is not an exclusive reservation transaction.
2. Removing the final newline from an otherwise valid ledger record was accepted on replay. A truncated file must disable live. Empty-file replay also permits silent history reset; fresh initialization needs a required format header, not an indistinguishable empty file.
3. Adapter records only outcome text and selected ID before exposing success. Full gateway receipt/trace/authority/account record ID are NOT persisted. Then it strips them into legacy M1 types and misleadingly maps commercial_binding_sha256 to candidate_set_digest. Those digests are different. This is not an acceptable production boundary.
4. OAuth has no active request deadline. Evaluation aborts its controller but directly awaits fetch/reader.read/response.text; an injected stalled transport/stream that ignores signal can hang forever. Need an explicit abort race covering headers and each body read, including OAuth.
5. Transport returns raw caught error messages to the caller/ledger, potentially leaking the token or provider-controlled text. Use fixed sanitized error codes/messages. Do not echo validation payload fields/values, raw error bodies, private paths or credentials into product responses.

## Required corrections — src/hosted/** and tests/hosted.test.ts only

A. Prefer a real HostedReviewClient with evaluate(request,binding) rather than forcing full provider evidence into legacy M1 EvaluateAdapter types. Binding is separate server-owned metadata: stable idempotency key, session/run identity, basis revision/digest, candidate ID -> exact local proposal payload hashes. Do NOT use context control selectors such as idempotency_key/session_id to control SDK policy. Keep provider hashes separate from locally computed request/candidate mapping hashes. Preserve the exact real envelope and account/evaluator receipt IDs, trace metadata, authority and raw known wire fields; no invented fallback provider values. If a legacy adapter remains, it must not fabricate cryptographic equivalences and must not be the primary controller interface.

B. Persist the immutable reservation before any network request, and the full validated envelope before returning completed selection/refusal. Return distinct completed/refused/unknown/rejected/disabled states (or an equivalent discriminated union); unknown is not merely an error string. A failed persistence step cannot expose a usable selection. Preserve raw request+key and session/basis/candidate mapping with every attempt. No retries, no new key escaping an uncertain review.

C. Make reserve and transitions exclusive across concurrent promises AND distinct ledger instances sharing the file. Use a scoped exclusive lock file (wx), reload/validate committed history under the lock, enforce total/session/active counts atomically, append+fsync, then release. A new reservation sees any prior untransitioned reserved record and refuses. No automatic stale-lock deletion. Transition only once from reserved to a terminal state; unknown remains reserved in allowance. Never reset counts on errors. Default ceilings10total/2per session/1active; reject nonfinite or nonsensical caps. Status/replay must not mutate or spend. Return defensive deep copies. Missing, empty-without-header, malformed/truncated/invalid-digest/hash-mismatch history disables. Require final newline, strict header/version/records, valid request JSON and recomputed body SHA-256, valid bindings; bounded stat/read and per-record size (allow full bounded receipt, e.g.256KiBrecord/8MiBfile). Explicit initFresh only on nonexistent file, mode0600; no implicit create during replay. Do not claim administrator tamper resistance: the operator controls local files.

D. Shared bounded read helper with an active abort deadline: race fetch and every pending reader.read against abort, cancel on overflow/abort without waiting forever, release reader lock, clear listeners/timers in finally. Native fetch may abort its stream but tests must also cover deliberately signal-ignoring injected fetch/streams. Do not buffer unbounded response.text. OAuth request<=4096bytes; response<=16KiB; evaluation body<=32768, response<=64KiB. Reject redirects and wrong media type. Token lifetime/scope checked, cache900s less60s margin; one exchange in flight. No token or secret enters ledger or error text.

E. Add regressions proving the actual guarantees, not just sequential mocks: simultaneous two reserves same instance; two instances sharing one file; valid JSON missing final newline; empty/truncated/headerless file; tampered stored body with unchanged digest; duplicate terminal transition; reservation retained after unknown/restart; full selected/refused provider receipt survives restart; failed receipt persistence returns no selection; stalled OAuth headers/body; stalled evaluation headers/body; exception containing credential/token canary never appears in returned result or persisted log; all current48tests (updated to new real client if necessary) still meaningful. Synthetic fixtures must start valid and mutation assertions should identify the intended boundary so unrelated validation failures cannot make negative tests pass accidentally.
